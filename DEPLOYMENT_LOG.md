# Звіт про розгортання Coin Ops на GCP: Проблеми та Рішення

Цей документ містить опис технічних складнощів, з якими ми зіткнулися під час деплою, та методи їх виправлення.

## 1. Проблеми з інвентаризацією та SSH
*   **Проблема**: Скрипт `dynamic_inventory.sh` не міг знайти дані Terraform через неправильні відносні шляхи.
*   **Рішення**: Переведено скрипт на використання абсолютних шляхів через `dirname $0`.
*   **Проблема (ProxyJump)**: Помилка `Invalid ProxyJump "ubuntu@"` — адреса бастіону виходила порожньою під час паралельних запусків Ansible.
*   **Рішення**: IP-адреси бастіону та бази даних тепер фіксуються у файлі `.env` один раз, що гарантує стабільність підключення.

## 2. Невідповідність конфігурації бази даних
*   **Проблема (Автентифікація)**: Ansible намагався підключитися як користувач `cognitor`, тоді як Terraform створив базу з користувачем `postgres`.
*   **Рішення**: Синхронізовано `db_user` у всіх конфігураціях.
*   **Проблема (Права доступу)**: Помилка `permission denied` при спробі виконати `ALTER DATABASE SET runtime.app_role`.
*   **Рішення**: На керованих базах (Cloud SQL) такі зміни обмежені. Ми перейшли на встановлення ролі лише для поточної сесії.

## 3. Обмеження хмарних сервісів (GCP Cloud SQL)
*   **Проблема (Розширення)**: Помилка `extension "pgmq" is not available`. Google Cloud SQL не підтримує це розширення.
*   **Рішення**: Змінено бекенд черг з `postgres` на `external` (RabbitMQ). Це зробило систему більш надійною та масштабованою.

## 4. Мережеві та SSL складнощі
*   **Проблема (Nginx)**: Перевірка здоров'я `https://localhost/health` видавала помилку `EOF`. Nginx відхиляв запити до `localhost`.
*   **Рішення**: Додано `localhost` у `server_name` конфігурації Nginx та встановлено прапор `default_server`. Внутрішня перевірка здоров'я переведена на HTTP (порт 80) для стабільності.

## 5. Брак ресурсів (RAM)
*   **Проблема (RabbitMQ Blocking)**: На серверах з 1 ГБ оперативної пам'яті RabbitMQ зупиняв роботу через "Memory Alarm".
*   **Рішення**: 
    1. Створено файл підкачки (**Swap**) на 1 ГБ на вузлі History.
    2. Збільшено ліміт пам'яті RabbitMQ (`vm_memory_high_watermark`) до **0.7** (70%).

## 6. Синтаксичні помилки та залежності
*   **Docker Compose**: Виправлено неправильний формат прокидання портів (`8000/tcp:8000` -> `8000:8000`).
*   **Залежності**: Додано автоматичне встановлення `postgresql-client` на вузлах для виконання міграцій.

---
**Статус**: Всі проблеми вирішені. Система працює стабільно в режимі реального часу.
